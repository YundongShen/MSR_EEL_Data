# MSR_EEL_Data

Data for Edit Entailment Learning (EEL), built from SWE-bench Full (2,291 instances).

## Tier definitions

| Tier | Definition |
|---|---|
| T1 | Gold-patch hunk whose file is linked to a fail-to-pass test (a test file imports a module matching the hunk's file path, or shares its package directory) |
| T2 | Gold-patch hunk with no such link |
| T3 | Hunk generated by `claude-haiku-4-5-20251001` that does not overlap the gold patch: its file is not in the gold patch, or its start line is at least 20 lines from every gold hunk start in that file |
| T0 | Evaluation only: gold hunks from other test-split instances of the same repository, used as distractors (at most 50 per instance) |

Split: 80/10/10 by instance, giving train 1,833, validation 229 and test 229.

## Counts

| | train | val | test | total |
|---|---|---|---|---|
| instances | 1,833 | 229 | 229 | 2,291 |
| T1 hunks | 2,662 | 277 | 415 | 3,354 |
| T2 hunks | 4,911 | 511 | 447 | 5,869 |
| instances with T3 | 581 | 80 | 82 | 743 |

T3 hunks: 1,257 in total. Generated hunks discarded because they overlap the gold patch: 2,866.

Evaluation uses the 82 test instances that have T3 hunks. T2-Recall uses the 47 of those that also have a T2 hunk.

## Layout

```
swebench/     raw SWE-bench instances (see swebench/README.md)
processed/    instances_full.jsonl.gz      parsed instances: requirement, fail-to-pass test functions, source units, gold hunks
generation/   haiku_generations.jsonl.gz   one Haiku generation per instance (2,291 records)
labels/       gold_hunk_tiers.jsonl        T1/T2 label of every gold hunk (9,223)
              tier3_hunks.jsonl            T3 hunks, one line per instance that has any (743)
              generated_hunk_decisions.jsonl  every generated hunk and whether it became T3 or was discarded (4,123)
              instance_status.jsonl        per instance: split, hunk counts, why it has no T3, whether it is evaluated
splits/       splits.json                  train/val/test instance ids
evaluation/   test_eval_sets.json          the 82 retrieval-evaluation instances and the 47 T2-Recall instances
              tier0_distractors_test.jsonl T0 distractors for each evaluated test instance
```

## Files

### processed/instances_full.jsonl.gz
Output of `scripts/parse_instances.py` (2026-05-10). Fields: `instance_id`, `repo`, `requirement`, `fail_to_pass_ids`,
`gold_hunks`, `source_units`, `test_functions`, `test_patch`. `gold_hunks[*].tier_label` is stored as null; tiers are assigned
when the file is loaded (`data/tier_labeler.label_instance_inplace`), and the result is in `labels/gold_hunk_tiers.jsonl`.

### generation/haiku_generations.jsonl.gz
Output of `scripts/generate_tier3.py` (run on 2026-05-12): model `claude-haiku-4-5-20251001`, temperature 0.7, max tokens 4096,
one sample per instance. Each record holds `meta` (`base_commit`, `problem_statement`, `gold_patch`, `fail_to_pass`) and
`generation` (`system_prompt`, `raw_response`, `extracted_diff`, `sr_blocks_found`, `sr_blocks_applied`, model settings).
Two large fields of the original output are left out: `source_files`, which is the same as in `swebench/`, and
`modified_files`, which can be rebuilt by applying `extracted_diff` to `source_files`.

### labels/gold_hunk_tiers.jsonl
`instance_id`, `split`, `hunk_id`, `filepath`, `old_start_line`, `tier` (1 or 2).

### labels/tier3_hunks.jsonl
`instance_id`, `tier3_hunks` (each: `filepath`, `old_start_line`, `hunk_diff`, `context_before`, `context_after`, `tier_label` = 3).

### labels/generated_hunk_decisions.jsonl
One line per hunk of `extracted_diff`: `instance_id`, `generated_hunk_index`, `filepath`, `old_start_line`,
`decision` (`tier3` or `discarded_overlaps_gold`), and `nearest_gold_start_same_file` (null when the file is not in the gold patch).

### labels/instance_status.jsonl
`instance_id`, `repo`, `split`, `n_gold_hunks_in_patch`, `n_tier1`, `n_tier2`, `sr_blocks_found`, `sr_blocks_applied`,
`n_generated_hunks`, `n_tier3`, `n_discarded_overlaps_gold`, `no_tier3_reason`, `in_retrieval_eval`, `in_t2_recall_eval`.

`no_tier3_reason`:

| value | instances |
|---|---|
| null (has T3) | 743 |
| `all_generated_hunks_overlap_gold` | 1,273 |
| `no_search_replace_blocks_in_response` | 248 |
| `no_block_applied_to_source` | 27 |

### evaluation/tier0_distractors_test.jsonl
`instance_id`, `tier0` (list of `source_instance_id`, `hunk_id`). The retrieval evaluation draws T0 distractors at run
time with `random.Random(42)`: test instances in file order, the pool is the same-repository gold hunks of the other test
instances, and `rng.sample(pool, 50)` is used when the pool has more than 50 hunks. The same generator also draws one
tie-break number per candidate after scoring. This file replays exactly that sequence of draws. If the evaluation is run
the same way, it draws these distractors.

## Checks
- Recomputing T3 from `extracted_diff` and the gold patch with the 20-line rule gives exactly `labels/tier3_hunks.jsonl`.
- The T1/T2, split and evaluation-set counts above were recomputed from the files in this repository.
